## 1 四层结构

用户的目标有三档优先级（最重要 / 核心 / 扩展）；再加上承载它们的**真源层**（本文件与「怎么检验」列），合起来是四层：

| 层 | 名称 | 内容 | 该层怎么算合格 |
|---|---|---|---|
| L0 | 真源层 | 本文件 + 每条目标的「怎么检验」 | 每条目标都能指向一条可跑的检验；优先级冲突以本表裁决 |
| L1 | 最重要 | 减少 AI 思考机会与长度 | 下一步/验收/语义由结构直接给出，模型只执行、不复述推理 |
| L2 | 核心 | 明确处理流程 / 明确结果验证 / 清晰语义定义 / 多 AI 并行不冲突 | 四件事各有唯一真源与机器守卫，互不替代 |
| L3 | 扩展 | 看见整体框架 / 看见语义变化 / 看见会话状态 | 只读可见；数据缺失时降级（隐藏或「—」），不抛错、不假 0 |

## 3 使用规则

1. **先定 id 再写代码**：PR / 任务描述里写清服务的 `id`（可多条）与对应检验；没有 id 的改动不做。
2. **检验优先于说明**：新增文案/文档不减少思考，只有把推理前移成结构（边表、模板、门禁、只读投影）才会减少；用第 2 节的检验列证明。
3. **一条目标可有多个落点，但同一件事只有一个真源**：落点缺失时先补落点，不新增平行机制。
4. **本文件只追加不重写**：优先级或措辞变化追加修订记录，保留历史，避免目标漂移。
5. **只读优先**：L3 的可见性落点若需要新增数据，优先从既有台账现算投影；不改写台账、不引入第二份状态。
