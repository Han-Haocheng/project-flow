# 长期项目会话连续性协议

目标：让长期项目不依赖任何人或会话的“记忆”。仓库、台账、任务书和 reflog 共同构成外部事实源，任何新会话都能据此无损续作。

## 1. 协作台账（COLLAB_STATE）

- 每个项目维护一份 `COLLAB_STATE.md`，模板见 [assets/collab-state.template.md](../assets/collab-state.template.md)。
- 关键字段：`state_version`、`updated_at`、`last_session`、`environment`、`baseline`、`last_known_good`、活跃任务、等待用户、归档区。
- 更新时机：派工前、交付后、发布后、用户确认后、每个 checkpoint 后；每次改动同步 `updated_at`。
- 禁止写入密钥、token、密码；相关字段用“见项目配置”代替。
- **台账只由协调者写入**：子代理通过独立文件（如 `.agents/heartbeat/<session>.json`、任务 status 文件）上报，协调者汇总；禁止多会话共写 `COLLAB_STATE.md` 造成互相覆盖。
- 台账损坏时按「2. 恢复协议」重建，不依赖单文件不可丢失。

## 2. 恢复协议（新会话 / 压缩 / 中断）

恢复会话的第一步固定为：

1. `git log -1 --oneline` 与 `git status --short`；
2. 读 `COLLAB_STATE.md`，再读当前任务书；
3. 核对远端、最近 CI/workflow 结果和工作区是否有离线期间的新变化；
4. 跑 `scripts/check_state.sh COLLAB_STATE.md` 做状态健康检查；
5. 双源校验：state、git、reflog 矛盾时以 git 为准，并回馈差异；
6. 若有未归属的未提交改动，先冻结并询问用户，不猜测、不自行提交；
7. 复跑受影响范围的门禁，不信任“上次验证过”。

续作判断：若任务仍为 confirmed、范围/基线/任务书未变，可直接续作；若范围、基线或任务书发生变化，先把变化回馈用户，重新确认后再续作。

台账损坏或无法解析时：用 git 历史、reflog、最近任务书与提交记录重建活跃清单；重建完成前不执行新动作。

不信任摘要和记忆：出现压缩提示、重复问已答问题、范围表述漂移、摘要与 git 矛盾时，立即回到第 1 步。

## 3. 心跳与跨会话令牌

- 子代理写独立心跳/状态文件（如 `.agents/heartbeat/<session>.json`），协调者汇总进台账；只有协调者写入 `COLLAB_STATE.md`。
- 只读调研可并行；写会话执行“串行令牌”：同文件域已有未过期 owner 时不写入。
- 心跳超过 30 分钟视为过期；接管流程：先把 owner 置为 pending（记录申请会话），给用户建议并等确认，确认后才改 owner，禁止双写。
- 接管时先 `git status` 复核归属，禁止双写。
- “已派工”不等于“已产出”：派工后记录 session，用 git status 与文件 mtime 核实，静默即为 orphan。

## 4. 授权与审批衰减

- 反驳纠错授权：代理有权也必须指出用户内容/建议中的错误、不合理或不建议之处，说明对未来项目的影响；普通任务说明理由后即可执行，不需要每条指令确认。
- 没有实质问题时明确说“没有异议，按你的意见执行”，不为反驳而反驳。
- 子代理发现任务书/协调者指令不合理，也必须反驳协调者，不照单执行。
- 任务书经用户确认后，子代理在任务书范围内向协调者负责，不再逐条找用户；范围外动作必须回到用户当次确认。
- 普通改动的确认写进 approved list（任务 id、范围、时间、任务书链接）。
- push、打标签、删除、改依赖、动发布分支、历史重写、`rm -rf` 类破坏性命令始终当次确认。
- 用户原话与关键限制原样记录，不转述；反驳与建议按 [assets/advice-format.md](../assets/advice-format.md)。

## 5. 上下文预算

- 会话启动只加载：台账、当前任务书、项目命令契约；references 一律按需读取。
- 台账分 Active 与 Archive；完成目标、旧决策、旧 checkpoint 定期归档。
- 状态文件超过 64KB 时先归档再继续，`check_state.sh` 会给出容量提示。

## 6. 恢复点与回滚

- 每个目标记录 `last_known_good` 基线和完成提交 hash。
- 恢复发现文件被改坏时，直接 `git checkout -- <file>` 回到 last-known-good 重做，不继续缝。
- 每个目标完成即提交，提交信息带 scope 前缀（如 `feat(frontend): ...`），便于 `git log --grep` 重建现场。
- 交付验收加入影响域/接口兼容检查（共享类型、API 契约、DB schema、配置引用），不只查文件存在与引用可解析。

## 7. 里程碑复盘

- 每个里程碑或每 N 个提交做一次复盘：无效交付、会话中断、越界改动、重复陷阱、技能更新建议。
- 复盘结论写入台账 Archive，可复用的教训合入本技能或其 references。
- 被反驳/拒绝的想法归档到 Archive/Rejected Ideas（含理由与替代方案），恢复或新任务前查重，避免重复提案。

## 8. 跨机器与跨配置

- 台账使用仓库根相对路径，不写私人绝对路径。
- 恢复时检查环境：git 版本、当前 profile/模型、可用工具；与上次记录不一致时先说明再继续。
- 换机器/换 provider 后不假定工具与权限一致，重新做环境能力检查。

## 9. 台账版本与入仓策略

- 台账维护 `state_policy`：默认 ignored（不入 git）；入仓与否由项目契约/AGENTS.md 决定。
- 入仓的台账不写本地绝对路径、密钥、token、密码与无关个人配置。
- 技能版本记录在 SKILL.md 顶部；台账 `state_version` 与协议版本不一致时先说明再续作。

## 10. 影响域与接口边界

- 任务书必须同时声明文件归属边界和影响域/接口边界：共享类型、API 契约、DB schema、配置引用、CI/发布工作流。
- 文件域不重叠不等于互不影响；涉及共享接口时先做依赖分析，验收时复跑受影响模块门禁并检查接口兼容。

## 11. 项目技能缺失兜底

- 项目技能缺失或过时时，协调者先与用户拟定最小命令契约（验证命令、版本声明位置、禁止项、分支约定），写入任务书后再开工。
- 最小契约允许项目技能更新后替换，替换后按新契约复跑门禁。

## Host 任务板卡片模式的重启恢复（2026-09-19 补充）

若写代理改成 Host 任务板上的卡片（见 SKILL.md §九），恢复语义与"子代理"不同，逐条记住：

- **卡片台账持久化并对账**：卡片定义、排期、执行记录都在 Host 侧权威台账里，进程重启后原样加载；运行中且**已记下会话 id**的执行会被逐个核对并结算（不会留假的"运行中"）。
- **半途未记下会话 id 的启动**：被结算成"取消"，**不重发**。
- **cron 错过的触发点**：跳过、**不补跑**（`nextRunAt` 从当前时间前滚）。
- **会话可续**：卡片开 `reuseSession` 后，重跑会**接着原会话的历史继续**（保留标题与上下文）；会话不存在或非空闲时自动新开会话，不阻塞调度。
- **看板绿 ≠ 交付**：结算只看 `turn/end` 的 reason 是否为 `error`，**被中断（`interrupted`）会被记成成功** ⇒ 复核必须看会话产出（有无实质文本、最后一次 `turn/end` 的 reason）。
- **协调者的后台任务不是恢复机制**：它们与 Host 同生共死，且死时不发通知；自动恢复要靠 **Host 侧**：看门狗卡（只读 + 定时，判"会话久未活动"或"假成功"后重跑，带重试上限）+ **Host 自启**（systemd user service / 启动器），否则重启后没有任何调度。
- **人工闸门**：卡片的有效权限高于部署默认值时，首次运行需要人确认一次；改权限或交接包会重新武装闸门；卡片创建卡片也绕不过（新卡仍未确认）。
