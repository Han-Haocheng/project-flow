# 新项目接入清单（通用技能）

> 适用：第一次在某个仓库使用 `ai-collaborative-dev-workflow`。
> 原则：技能是流程，项目契约是参数；**不要把技能复制进仓库**。

## 1 流程只有一条：中心-贡献者

| 角色 | 谁 | 职责 |
|---|---|---|
| 中心 | 项目维护者 / 主工作区会话 | 唯一合并主分支、唯一写台账、决定合并顺序；按五条清单判定每份提交 |
| 贡献者 | 子代理 / 队友 / 外部协作者 | 在自己分支提交、跑门禁、按模板提评审申请；不合并、不 push、不写主分支台账 |

单人就是"中心与贡献者合一"：直接提交，但门禁与 CHANGELOG 纪律不变。**这不是模式开关**——出现第二个写者就按角色分工，不需要改建制。

## 2 写命令契约（必须）

放在 `AGENTS.md` 或一个很小的项目技能里，至少包含：
- 工作分支与发布分支；
- build / test / lint / smoke 命令，没有的项写“无”；
- 版本声明位置（哪些文件要同步版本号）；
- 发布方式（手动 / CI / 不打版）；
- 依赖与临时执行器禁令；
- CHANGELOG 策略。

### 已有协议/项目技能时

先读仓库现有的 `PROTOCOL.md` / `AGENTS.md` / 项目技能。命令契约已经存在就不重写；`AGENTS.md` 最多做指针。**禁止**复制规则或另建第二套台账。

### AGENTS.md 最小模板

~~~md
# 项目协作约定

- 分支：dev 单线开发；发布分支只接收合并。
- 构建：`pnpm build`
- 测试：`pnpm test`
- Lint：`pnpm lint`
- 版本位置：`package.json`
- 发布：打 `v*` 标签触发 workflow。
- 依赖：不新增依赖；不用 npx / pnpm dlx。
- CHANGELOG：发布时生成，代理不手写。
- 禁止：force push、直推发布分支、`git add -A`。
~~~

## 3 项目技能（需要时）

满足任一条件再建项目技能，否则 `AGENTS.md` 足够：
- 命令契约超过 20 行；
- 工具有特殊禁令或版本陷阱；
- 有多个模块、发布链或事故案例需要长期记录。

项目技能只写：命令契约、版本位置、分支/发布、接口边界、事故案例。
精度层、协作流程、台账模板一律指向通用技能，不复制。

## 4 精度层（工具，不是模式）

适合：多代理并行、任务需要跨会话交接、希望用脚本校验任务书/文档。

需要准备：
- `.agents/gate-config.json`：scope、版本/令牌/schema/API 同步项、命令；
- `.agents/tasks/`：任务 JSON；
- `.agents/doc-standard.json`：模糊词表与行数上限；
- 参考实现：通用技能 `scripts/task`、`doc_check.py`、`gate.py`、`precision_common.py`；复制到 `.agents/scripts/`。

**当前状态**：参考实现已提供；hooks/CI 接入示例见项目的 `gate-config`（先 observe，再阻断）。
新项目先按契约手工执行，再按 observe → 阻断的顺序接 hooks/CI。

## 5 接入顺序（先 observe 再阻断）

- 先 observe：只告警，不阻断，收集误报。
- 再接 pre-commit / pre-push。
- CI 最后设为 required check；分支保护不在 workflow 文件里，需要仓库设置。

## 6 验收清单

- [ ] 任务书含 base、允许文件域与证据要求；贡献者能按模板提申请。
- [ ] `AGENTS.md` 有可执行的 build/test 命令。
- [ ] 版本位置、发布方式、分支规则已写清。
- [ ] 仓库里没有复制通用技能或重复 schema。
- [ ] 精度层如启用，配置在项目内，模型在通用技能里。
- [ ] 如果接了 hook/CI，先跑过一次正例和一次反例。
- [ ] 已有协议的项目：只补缺口，没有复制规则或另建台账。

## 7 常见错误

- 把通用技能整个复制进仓库，产生第二份真相。
- 一上来就搭多中心 / 令牌 / 文件锁：不需要；冲突由中心在合并阶段裁决。
- 命令契约只写“见 README”，等于没写。
- 精度层和 Markdown 任务书并行维护两套状态。
- 没有 CI 却先接 required check，红绿都拦不住。

## 8 什么时候需要拆分中心与贡献者

- 出现两个以上写者同时改不同文件域；
- 需要跨会话交接任务状态；
- 需要无人值守或定时执行；
- 发布需要多个审批点。

出现任一情况再拆分角色；拆分只增加分工，不重写命令契约。
