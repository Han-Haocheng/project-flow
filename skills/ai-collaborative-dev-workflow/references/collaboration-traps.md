# 环境、协作与工具调用陷阱

## 文件修改工具纪律（高发）

1. **多行脚本/代码绝不内联**：python/bash/Rust 片段先写成文件（如 `/tmp/x.py`、仓库 `scripts/` 内），再用一条极简命令执行；需要拼装时也先写"片段文件"，不在 JS 数组或模板字符串里拼行（漏一个引号前缀就整段语法错误）。
2. **锚点失效**：同一文件的连续编辑，每次 edit 前重读目标区段；read 与 edit 之间不要先跑 `fmt` 等格式化（`file changed since read` / `old_string not found`）。
3. **批量/长文档改动走 diff 合并**：整文件读（先确认断言行数 == `totalLines`，读不完整就拒写）→ 内存变换 → `diff -u --label a/<rel> --label b/<rel> 旧 新` 生成仓库相对路径补丁 → `patch -p1 --forward` 应用；出 `.rej` 立即停手人工处理。**只有新建文件才整文件 write**，不要用"读前几十行 + 整文件写回"的方式改已有文件（曾截断 CHANGELOG）。
4. **字符串展开陷阱**：向字符串数组插入文本前先 `section.split(chr(10))`；插入后用"总行数 + 单字符行计数"自检；长文档改完通读一遍。
5. **路径/cwd 假设错误**：脚本内一律用仓库根相对路径，并在同一条命令显式 `cd` 到仓库根；或脚本开头断言关键路径存在。
6. **破坏性 shell 自伤**：`pkill -f <pattern>` 会匹配到包装自身的命令行，把自己的任务杀掉；先 `pgrep -f '<pattern>$'` 确认 PID 再 `kill <pid>`。`git add` 永远逐文件（禁止 `-A`）；`rm` 前先 `ls`。
7. **改坏文件不要继续缝**：同一文件被改坏两次后立即 `git checkout -- <file>` 回退再干净重做。
8. **编辑链部分成功**：一次调用中的多个 edit 顺序执行，中途报错时**前面的已生效**；重试前先读文件核对现状（含 CRLF 与行内容差异），勿盲目重发。

## 结论与断言

- **grep 的结论会骗人**：嵌套 `use crate::{ ... search::SearchService }` 不含字面量 `crate::search`，据此断言"core 不依赖 search"是错的；统计 `fn host_of` 会把同名测试函数算成第二份实现。架构性断言（依赖方向、重复实现、死代码）必须用第二种方法复核：编译错误、读实际导入块、`cargo tree`、运行时行为。
- **音源/网络问题先分清宿主缺陷与上游不可达**：用 `--no-network` 复现，不要把 UNREACHABLE 当 FAIL 去改实现，也不要把 FAIL 当网络问题跳过。

## 门禁与验证

- **门禁就近跑**：结构性改动后立刻跑就近门禁（fmt/test/build），让损坏几分钟内暴露，不流进提交。
- **静态检查盲区**：动态 import/反射、宏与模板生成代码、`include!` 引入的生成文件、build.rs 产物、前端动态 `import()`、Tauri capabilities/permissions 清单、内嵌脚本块、配置引用——必须补扫或人工核查。
- **忽略规则误删**：删任何 lint/构建 ignore 或 exclude 前先全仓试跑验证其**实际匹配的文件**（basename 模式匹配任意深度，"顶层目录不存在"不代表深层没有同名文件；案例：曾致深层同名产物被扫出 2195 个错误）。
- **配置类改动必须真实产物验证**：改打包/updater/签名/CI 配置后至少本地跑一次目录级产物验证，否则错误只会在集成或 CI 阶段爆出。
- **并行代理构建冲突**：多个代理同时构建/冒烟会竞争共享产物目录（`src-tauri/target/`、`dist/`、`.cache/` 等）——任务书约定"检测到并发构建（`ps` 或产物 mtime）则跳过本地验证，由协调者收敛后统一执行"。

## 协作管理

- **子代理「已派工」不等于「已产出」**：派工后要用 `git status` + 文件 mtime 核实是否真的落盘；长时间无改动就中断代理、由协调者接管（同一文件域禁止双写）。被中断的代理停留在 ready 状态可唤醒，但唤醒不保证恢复，关键路径宁可自己接手。
- **交付验收**：产出物路径是否存在 → 引用与接口是否都能解析（相对路径、模块声明、import、共享类型/API 契约）→ 事实是否零丢失（用生成物做权威清单逐条核对）；缺件由协调者补齐，不让代理二次往返。
- **基础设施不可用时降级兜底**：子代理基础设施整体不可用，协调者降级直实施（门禁与纪律不变），恢复后再派代理。
- **反驳纠错优先（本技能最高硬性约束）**：用户和任务书/协调者提出的错误、不合理或不建议内容都必须指出，说明理由、影响与替代方案；没有实质问题时明确说没有异议；普通任务反驳后直接执行，敏感/范围外动作当次确认。
- **主工作区勿手动切分支**：误切后 `git switch dev` 无损恢复，不要 `reset --hard`；reflog 是查"谁做了什么"的第一现场。
- **工具链只用契约内命令**：禁止临时执行器（npx 等）与自作主张的依赖变更；本地缺包时直调已安装入口或上报协调者。
- **提交未带 pathspec 会吞并他人已暂存内容**（真实案例：一个提交混入 45 个无关文件、消息失实）→ commit 必带 pathspec，提交前 `git diff --cached --stat` 自检"我改的文件"与"我 add 的文件"一致；并行波次越界改动即使正确也算缺陷。
- **CHANGELOG 空缺会让发布说明降级**：每次提交同步写 `[Unreleased]`，CHANGELOG 随提交（项目另有约定时以项目为准）。
- **台账也会过期**：`COLLAB_STATE.md` 与 git/reflog 矛盾时以 git 为准；恢复会话先 `check_state.sh`，台账有版本/更新时间/last_session 仍不能免检。
- **台账共写会互相覆盖**：`COLLAB_STATE.md` 只由协调者写入；子代理用独立心跳/状态文件上报，协调者汇总，禁止多会话共写台账。
- **离线期间外部世界会变**：恢复前核对远端 refs、CI/workflow 结果、工作区新改动；离线时可能已经发布、被提交或被别台机器改动，旧任务书不一定仍有效。
- **审批衰减 / 上下文预算 / 心跳令牌 / 接管 pending** 等长期协议细节统一见 [references/session-continuity.md](session-continuity.md)，不在本文件重复。
- **摘要与记忆不可信**：出现压缩提示、重复问已答问题、范围表述漂移、摘要与 git 矛盾时，立即回到恢复协议重新读台账与仓库。
