# 任务书模板

> 给子代理派活时复制本模板；未填项为协调者必填，禁止让代理自行推断归属边界。
> 任务书经用户确认后，即授权本书范围内执行，范围内不再逐条等用户；范围外动作必须回到用户当次确认。
> 子代理不直接写 COLLAB_STATE；心跳/进度写独立文件，由协调者汇总。子代理发现本书内容不合理时必须反驳协调者，不照单执行。

## 验收与检查点

- 两遍法：实现遍结束后，从任务目标反推验收清单，逐条对照代码核对，不看着代码自证。
- 检查点：每个可验证切片结束记一行（改动文件、门禁结果、遗留），写心跳或提交 body，不新建文档。

## 提交规范

- 提交类型：`feat/fix/docs/chore/ci/refactor/style` + 中文说明；每个可独立验证的步骤一次提交。
- CHANGELOG：默认 `[Unreleased]` 随提交写入（项目另有约定时遵项目）。
- 提交命令：`git commit -m "..." -- <自己的文件>`；提交前 `git diff --cached --stat` 自检。

## 禁止项

- push / 切分支 / fetch
- `git add -A`
- 修改归属外文件
- 安装或升级依赖
- 使用契约外工具/临时执行器
- 失败后盲目重试
- 未读状态文件 / 未核对基线就动手
- 把密钥 / token / 密码写进台账
- push / 打标签 / 删除 / 改依赖 / 动发布分支 / 本地历史重写（reset --hard、rebase、commit --amend）/ `git clean -fd` / 改 CI、发布工作流、版本声明 / `rm -rf` 类破坏性命令（除非本书已登记并获得当次确认）
- 明知用户建议不合理、会污染未来项目仍照单执行（应先反驳并回馈）
- 直接写 COLLAB_STATE（子代理）

## 停止条件

- 门禁变红 / 合并冲突 / 脚本中途失败：保留现场，停止并上报协调者。
