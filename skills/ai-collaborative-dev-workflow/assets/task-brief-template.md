# 贡献者须知（派工模板）

> 中心给贡献者（分析者 / 实现者 / 审查者 / 子代理 / 外部协作者）派活时复制本模板。**未填项由中心补全**，禁止让贡献者自行推断 base 与归属边界。
> 任务书经用户确认后，即授权本范围内执行，范围内不再逐条等用户；范围外动作必须回到用户当次确认。
> 贡献者不写主分支台账；发现本书或中心指令不合理时必须反驳中心，不照单执行。
> **组队时（Agent Teams）**：一张 Team 任务卡对应**一个角色**；派工正文就是本任务书，`description` 按「角色与状态」节写死（`flow:` / `role:` / 实现者 `domain:`），不要只贴卡 id 让队友猜。角色定义见 `SKILL.md` §10.2，状态机见 §10.3，交接物见 §10.4。

## 角色与状态（组队时必填）

- 角色（`role`）：`analyst` / `implementer` / `reviewer`（一张卡一个角色）
- Team 任务 id：`task-<N>`；`description` 标注：首行 `flow: <T-id>`，第二行 `role: <...>`，实现者第三行 `domain: <path prefix>`
- 状态机位置（`SKILL.md` §10.3）：`pulled` / `analyzing` / `assigned` / `implementing` / `reviewing` / `accepted` / `rejected` / `merged` / `reclaimed`——**本卡从 ____ 推进到 ____**
- 交接物与下一手：
  - 分析者 → **任务书**交给中心（中心确认后下发给实现者/审查者）
  - 实现者 → **提交 + 证据 + 评审申请**交给审查者（中心同读）
  - 审查者 → **结论 + 证据**（accept / reject / request-rebase）交给中心
  - 中心 → **项目台账更新 + Team 卡回收**（`team: <taskId>` 回记）

## 工作方式（按角色执行）

- **分析者（只读）**：读仓库/契约/任务，产出任务书（目标、范围/base、文件域切分、验收标准、验证命令、风险、依赖）；**不写代码、不提交、不改任何文件**；文件域切不开时交回中心决定串行。
- **实现者**：有 `create_worktree` 时**自己**调用（工具只创建、不合并，且会切走调用者 cwd）；没有时用普通本地分支 `git switch -c <task-id>-<slug> <base>`；**只改 `domain:` / 允许文件域内的文件**。
- **实现者必须提交**：改动以提交形式交付（每个可独立验证的步骤一次），**申请前不得留未提交改动**；只 `git add` 允许文件域内的文件，commit 带 pathspec（`git commit -m "..." -- <file>`）。
- **实现者必须给证据**：每步跑验证命令，申请里写命令原文 + 退出码/摘要，不写"测试通过"四个字。
- **审查者（只读 + 跑测试）**：独立复核 diff / 范围 / 测试 / 契约影响，按 `SKILL.md` §1.4 五条清单逐条给结论，结论为 **accept / reject（具体理由）/ request-rebase（新 base）** + 证据；**不改代码、不合并、不写台账**，且不能是实现者本人。
- **完成后**：实现者按 [merge-request-template.md](merge-request-template.md) 提评审申请（task id、贡献者、branch、worktree path、base commit、commits、改动文件、测试命令与结果、影响面、风险/未完成、希望中心做什么）；审查者按结论格式回中心；分析者交任务书。
- **等结论**：accept（中心合并）/ reject（按理由重做或放弃）/ request-rebase（rebase 到新 base、复跑、重新提申请）。贡献者不自行合并，也不在中心的主工作区解冲突。

## 检查点

- 两遍法：实现遍结束后，从任务目标反推验收清单，逐条对照代码核对，不看着代码自证。
- 审查者做独立验证：从申请与验收标准反推检查项，**不沿用实现者的自证**；能跑的命令自己再跑一遍。
- 每个可验证切片结束记一行（改动文件、门禁结果、遗留），写心跳或提交 body，不新建文档。

## 提交规范

- 提交类型：`feat/fix/docs/chore/ci/refactor/style` + 中文说明；每个可独立验证的步骤一次提交；message 带 task id。
- CHANGELOG：默认 `[Unreleased]` 随提交写入（项目另有约定时遵项目）。
- 分支与工作树：`branch` + `path` + `commit` 三处信息在申请、任务 notes 与心跳里保持一致。

## 禁止项

- 实现者：merge / push / 切主分支 / rebase 他人分支 / 删除分支或工作树 / 写主分支台账 / **审自己**；在主分支或主工作区直接提交。
- 审查者：改代码（问题回实现者）/ merge / push / 写项目台账。
- 分析者：写代码 / 提交 / 改文件。
- 任何人：`git add -A`；修改允许文件域之外的文件；安装或升级依赖；使用契约外工具/临时执行器。
- 失败后盲目重试；把密钥 / token / 密码写进提交、台账或申请。
- 打标签 / 删除 / 改依赖 / 动发布分支 / 本地历史重写（reset --hard、rebase、commit --amend）/ `git clean -fd` / 改 CI、发布工作流、版本声明 / `rm -rf` 类破坏性命令（除非本书已登记并获得当次确认）。
- 明知用户建议不合理、会污染未来项目仍照单执行（应先反驳并回馈）。
- 直接写 COLLAB_STATE（贡献者）。

## 停止条件

- 门禁变红 / 合并冲突 / 脚本中途失败 / base 与任务书不一致：**保留现场**，停止并上报中心，不自行 rebase 或 reset。
- 发现任务书范围与仓库现状矛盾：先回馈中心，等确认再动手。
- 审查者发现"实现者=审查者本人"或角色标注缺失：停止复核并上报中心，不代签结论。

## 完成报告格式

- 角色 / domain（实现者）/ Team 任务 id
- 改动清单（实现者）或结论清单（审查者）或任务书要点（分析者）
- 行为说明
- 验证摘要（命令 + 退出码）
- 提交 hash 与 branch + path（实现者）
- 验收清单逐条结论（对照需求，不对照代码）：
- 影响域 / 接口兼容性验证摘要：
- 允许文件域之外的改动（如有，必须单独说明；通常应为"无"）
- 当前状态机状态 + 下一手交给谁
