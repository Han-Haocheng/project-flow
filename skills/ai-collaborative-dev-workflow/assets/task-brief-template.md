# 贡献者须知（派工模板）

> 中心给贡献者（子代理 / 队友 / 外部协作者）派活时复制本模板。**未填项由中心补全**，禁止让贡献者自行推断 base 与归属边界。
> 任务书经用户确认后，即授权本范围内执行，范围内不再逐条等用户；范围外动作必须回到用户当次确认。
> 贡献者不写主分支台账；发现本书或中心指令不合理时必须反驳中心，不照单执行。

## 工作方式（贡献者须知）

- **自己建分支**：有 `create_worktree` 时**自己**调用（工具只创建、不合并，且会切走调用者 cwd）；没有时用普通本地分支 `git switch -c <task-id>-<slug> <base>`。
- **必须提交**：改动以提交形式交付（每个可独立验证的步骤一次），**申请前不得留未提交改动**；只 `git add` 允许文件域内的文件，commit 带 pathspec（`git commit -m "..." -- <file>`）。
- **必须给证据**：每步跑验证命令，申请里写命令原文 + 退出码/摘要，不写"测试通过"四个字。
- **不得越权**：不合并、不 push、不打标签、不切主分支、不 pull/fetch、不改他人分支、不写主分支台账、不安装或升级依赖、不用契约外工具/临时执行器。
- **完成后按模板提申请**：[merge-request-template.md](merge-request-template.md)——task id、贡献者、branch、worktree path、base commit、commits、改动文件、测试命令与结果、影响面、风险/未完成、希望中心做什么。
- **等中心结论**：accept（中心合并）/ reject（按理由重做或放弃）/ request-rebase（rebase 到新 base、复跑、重新提申请）。贡献者不自行合并，也不在中心的主工作区解冲突。

## 检查点

- 两遍法：实现遍结束后，从任务目标反推验收清单，逐条对照代码核对，不看着代码自证。
- 每个可验证切片结束记一行（改动文件、门禁结果、遗留），写心跳或提交 body，不新建文档。

## 提交规范

- 提交类型：`feat/fix/docs/chore/ci/refactor/style` + 中文说明；每个可独立验证的步骤一次提交；message 带 task id。
- CHANGELOG：默认 `[Unreleased]` 随提交写入（项目另有约定时遵项目）。
- 分支与工作树：`branch` + `path` + `commit` 三处信息在申请、任务 notes 与心跳里保持一致。

## 禁止项

- merge / push / 切主分支 / rebase 他人分支 / 删除分支或工作树
- 在主分支或主工作区直接提交、写主分支台账
- `git add -A`；修改允许文件域之外的文件
- 安装或升级依赖；使用契约外工具/临时执行器
- 失败后盲目重试；把密钥 / token / 密码写进提交、台账或申请
- 打标签 / 删除 / 改依赖 / 动发布分支 / 本地历史重写（reset --hard、rebase、commit --amend）/ `git clean -fd` / 改 CI、发布工作流、版本声明 / `rm -rf` 类破坏性命令（除非本书已登记并获得当次确认）
- 明知用户建议不合理、会污染未来项目仍照单执行（应先反驳并回馈）
- 直接写 COLLAB_STATE（贡献者）

## 停止条件

- 门禁变红 / 合并冲突 / 脚本中途失败 / base 与任务书不一致：**保留现场**，停止并上报中心，不自行 rebase 或 reset。
- 发现任务书范围与仓库现状矛盾：先回馈中心，等确认再动手。
